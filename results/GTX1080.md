# GTX 1080 validation

## Stage 01 — validated

User-supplied container output confirms compilation and execution on
`NVIDIA GeForce GTX 1080`, compute capability 6.1, with CUDA image 12.2.2.
Driver and exact toolkit build versions were not included in the captured output.

All exhaustive CPU comparisons passed: random/zero inputs at `(17,19,23)`,
signed extremes with K from 1 through 7, and all three square benchmark sizes.
The GEMM SASS contains `IDP.4A.S8.S8` for `sm_61`.

| M = K = N | Median kernel time (ms) | INT8 TOPS |
| --- | ---: | ---: |
| 128 | 0.0201 | 0.2089 |
| 256 | 0.0966 | 0.3474 |
| 512 | 0.6005 | 0.4470 |

Five warmups, 20 timed launches, two operations per multiply-add. Gate 01 passed;
no performance threshold applies to the naive kernel. Sanitizer results were
not supplied.

## Stage 02 — stride-65 baseline validated, tuning pending

User-supplied GTX 1080 output confirms all small CPU comparisons and aligned
cuBLAS comparisons passed. All six large matrices passed exhaustive cuBLAS
comparison and the 64-position CPU reference. cuBLAS reported version `120205`.
The SASS confirms native `IDP.4A.S8.S8`.

The original 64×64×32 kernel, with shared stride 65, uses 56 registers,
4160 bytes shared memory, zero stack frame and zero spill stores/loads.

### Stride comparison — awaiting GPU validation

The current executable compares the original stride 65 with stride 68 using
the same inputs and measurements. Compilation, correctness, ptxas resource
usage and speedup of the two-specialization build remain to be checked on GPU.
No throughput improvement is claimed yet. The historical table above is from
the single-kernel build; use the same-run comparison to assess the padding change.

## Reproduce

Run inside the development container on the NVIDIA machine:

```sh
nvcc --version
nvidia-smi
make all
make run
make run-gemm-naive
make sass-gemm-naive
make check-gemm-tiled
make run-gemm-tiled
make sass-gemm-tiled
```

Record the test date, GPU, driver and toolkit versions, benchmark output, and
confirmation that `IDP.4A` appears in the GEMM kernel's SASS. Record whether an
optional Compute Sanitizer run passes as well.

For stage 02, archive both backend timings, their throughput ratio, CPU packing
time, ptxas register/spill reports and confirmation of native signed DP4A.
Correctness is mandatory; review performance before advancing to stage 03.

The previously reported DP4A result (~13.98 TOPS) has no captured output in this
repository; rerun stage 00 to archive reproducible evidence.
